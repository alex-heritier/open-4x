# Open 4X

An independent Rust strategy game set in the industrial age. The default campaign is **the whole world on Saturday, 1 January 1876**: an upright Mercator map of 175,104 tiles (84°N to 58°S, so no Antarctica) painted from real climate, elevation, and river data, with 119 nations, from the British Empire and Qing China to the Kingdom of Hawaii, the Maori King Movement, and the Emirate of Bukhara, 612 starting cities, and eight wars already under way. One turn is one calendar day.

The game combines exploration, city founding, industrial development, research, recruitment, occupation, and unit-by-unit warfare on a Civ3-style board. Every soldier, gun, worker, and ship is an individual unit that moves square by square (eight neighbours), fortifies, and fights Civ3's round-by-round combat. Cities own a fixed cultural border and are drawn in the architecture of their nation's cultural flavor, and workers build roads, railroads, mines, and farms. Capture every enemy city or accumulate industrial output to win.

Campaigns are described by a standalone, versioned **scenario format** (a calendar start date, a map, nations, cities, starting units, and wars in one JSON document). See [`docs/scenario-format.md`](docs/scenario-format.md). The bundled world scenario is generated by `tools/scenario-forge`. The compact two-empire starter, `dawn-straits`, ships alongside it.

This is a playable first slice, not a complete commercial 4X. Diplomacy, trade, a technology tree, accessibility, multiplayer factions beyond the solo campaign, and polished painted art are future work. The reference images guide the isometric map, fleet/army presentation, parchment inspector, and campaign dispatches. Every shipped asset is original procedural art (the unit animations are rendered from 3D puppets built in code); the world's coastlines, rivers, elevation, and climate come from public geographic data (Natural Earth, ETOPO5, Köppen–Geiger; see `assets/PROVENANCE.md`).

## Run

From this directory:

```sh
cargo run                                            # the world in 1876, commanding Japan
cargo run -- --nation united-kingdom                  # the same world as another nation
cargo run -- --scenario dawn-straits                  # the compact two-empire starter
cargo test --workspace                               # simulation, content, runtime, client, protocol, and tool tests
cargo run -p fourx-server -- --list                    # scenarios and the nations you can command
cargo run -p fourx-server -- --simulate 10 --seed 42
```

The desktop client starts an embedded authoritative host. Bevy never mutates the simulation directly. The map opens on the commander's capital; the title bar shows the scenario and the date, and the day button shows today's date and advances one day. The 1876 world is *charted*: every nation knows the geography, borders, and cities from the first day, but enemy units are only seen within sight of your own units and cities. Other scenarios can start in fog. The fog of war follows Civ3: land you have never seen is black, land you have seen but nothing of yours watches now is dimmed and shows what you last saw (cities stay on the map, units and new borders do not), and the edge between them fades smoothly instead of stepping tile by tile.

Left-click one of your units (click again to cycle a stack) or a roster entry to select it. Right-click a square to order it there: it walks the cheapest route over several turns and keeps going until it arrives; right-clicking an enemy attacks it (or, for artillery, bombards it from one square away). Cities are selected by clicking them. Keys: Space ends the day (while a fight is on screen it skips the fight instead); Tab cycles units that still have moves; C cycles cities; H or Home returns to the capital; **F** fortifies; **B** founds a city with pioneers; **R** builds a road, then a railroad, with workers or pioneers; **M** digs a mine; **I** irrigates a farm; Delete or Backspace cancels a unit's orders; 1–6 select the displayed production designs; E develops the selected city; F5 saves; Escape deselects; arrows/WASD pan; wheel zooms. The minimap shows the map as it stands on screen with every nation's territory (fog included); click or drag on it to jump anywhere, and the outlined box is what the camera sees. Touch uses taps and two-finger pan/pinch. On small screens the inspector moves below the map and supports swipe scrolling.

Useful client flags: `--scenario ID`, `--nation ID`, `--seed N`, `--pack DIR`, `--zoom SCALE` (0.4 to 4), `--focus X,Y` (start the camera on a tile), `--load SAVE`, `--combat-speed N` (scale fight playback, default 1; also `FOURX_COMBAT_SPEED`), `--demo-combat NAME[@SECONDS]` (play a hand-made fight, see [`docs/combat-animation.md`](docs/combat-animation.md) §10).

Save with F5 or the Save button; resume with `cargo run -p fourx-client -- --load dawn.save.json`. Custom saves require the matching `--pack` for their artwork. Browser saves use local storage and resume with `?load=browser`. Saves from earlier builds (save format 1) cannot be loaded.

### The world scenario at scale

The map is far larger than the screen, so the client only builds sprites near the camera and rebuilds them when you pan beyond the built margin; territory borders and fog are drawn from the map's owner layer and the player's sight for the visible tiles only. A turn with all 119 nations takes roughly 10–25 ms in a release build early on and more as wars spread. Computer nations only chase targets within 48 tiles and cap their pathfinding, which keeps a year of play (366 turns) to about half a minute headless.

## Rules in this slice

The map is a Civ3 square grid with eight neighbours (diagonals count as one step). Movement is counted in thirds of a move: rough ground costs its whole move cost, a step between roads costs a third, and a step between railroads is free. Cities count as railroad. A unit with any movement left may always take a step. Orders given with a right-click persist as a goto; the unit keeps walking each day, and the computer nations use the same pathfinder.

**Units** are individual pieces with hit points by experience level (Conscript 2, Regular 3, Veteran 4, Elite 5, plus the design's own), movement, and a standing order. The base pack ships ten designs:

| Design | Attack / Defense | Moves | Notes |
| --- | --- | --- | --- |
| Line Infantry | 4 / 4 | 2 | The all-rounder; fortifies for +25% defense. |
| Dragoon Cavalry | 8 / 2 | 3 | Blitz: may attack again while it has movement left. |
| Field Artillery | none | 2 | Cannot attack or defend. Captured if it is alone when an enemy steps in. Bombards from one square away. |
| Workers | none | 2 | Build roads, railroads, mines, and farms. Captured if caught. |
| Pioneers | none | 2 | Found cities and work at half the rate of workers. |
| Ironclad Squadron | 4 / 4 | 4 | Sea unit; fights ships and shore. |
| Steam Transport | none / 3 | 4 | Carries up to 8 land units. Cannot attack. |
| Battleship | 12 / 8 | 3 | The heaviest hitter afloat (+2 hit points). Slow. |
| Protected Cruiser | 6 / 6 | 5 | The all-rounder of the fleet and the fastest ship (+1 hit point). |
| Torpedo Boat | 8 / 2 | 3 | Fragile and slow. **Lethal bombardment** from one square away: its volleys sink ships and kill land units. |

**Naval units** follow Civ3. A ship moves on water and may also enter a coastal city of its own nation (a port), crossing it to reach another sea; it can never enter any other land square, nor a rival's city. New ships are launched into the city that built them, and ships mend only in port. A ship in port cannot defend the city (its land defenders do), but it can still be shelled, and shelling it is easier than shelling a ship at sea; ships shooting at a port pick off its ships before its land units. A **transport** carries land units: step a unit onto an adjacent friendly ship that has a free berth to board (it costs one step), or use `Load` when both share a port square. Passengers ride along, never defend, and cannot fight, found, work, or fortify until ashore. A unit lands by moving from the ship to adjacent land, which ends its move for the day; in port, `Unload` sets passengers down without a step. A ship sunk or disbanded at sea takes its passengers with it, while one lost in port lets them step ashore.


**Combat** follows Civ3: each round the attacker wins with probability `A / (A + D)`, where the defender's strength is multiplied by terrain, fortification, and city-size bonuses; the loser of a round loses one hit point, and the fight runs to the end of one side's hit points. The best defender on a square is chosen by rating. Fast units may withdraw at one hit point. Bombardment wounds but never kills (volleys stop at one hit point) unless the shooter's design is lethal against that kind of target, and it cannot take a square; defenders may bombard back; a lone defenseless unit is captured instead of killed. Winners may be promoted by dice. The unit panel shows the estimated odds before you commit.

**Fights on screen** play out round by round. The simulation settles a fight in one step and keeps a record of it; the client replays that record, so what you watch is what already happened, and no animation can change a result. Both sides swing every round and the round's loser takes the blow and loses one hit point, shown on a bar over each fighter. Infantry fire volleys, cavalry charge, guns recoil, and ships fire broadsides, with a shell in flight for bombardments (a missed shell lands short, splashing at sea and raising dust ashore). A defender with a gun on the square may fire first, a loser falls or sinks, a retreat shows no death, a winner may be promoted (sparkles), and captured units take on their captor's colour. Fights play one after another, only when they are in view (the rest are dropped), and speed up when many are queued, so a turn of computer play does not hold you up. Orders wait until the fights are over; **Space, Enter, or the Skip button** ends them at once. Every unit is animated frame by frame, in Civ3's eight facings: it breathes and glances about while it stands, walks (or steams) square by square when it moves, and plays its own volley, charge, gun or broadside, cheer, and fall or sinking in a fight, with the procedural recoils, lunges and fades on top. Sound effects are synthesized, and a pack may restyle fights through `visuals.combat` and the unit clips through `visuals.units` in `pack.json`. The behaviour is specified in [`docs/combat-animation.md`](docs/combat-animation.md).

**Units walk.** The simulation writes down each walk of a command, square by square, beside its fight records, and the client replays it: a unit steps from square to square with its walk clip (a long railway journey speeds up to fit two and a half seconds), turns to face each step, and keeps facing the way it last went or fought. Walks of other nations show only where you can see them. Fights wait for the walks of the same turn; orders do not. Units nobody has turned face south-west, toward the viewer, as in Civ3.

**Cultural borders** are fixed per city. Each city has a border level from 1 to 6 (9, 21, 37, 61, 89, or 137 tiles; open water only near the coast) that never grows or shrinks over time. Whoever holds the city owns its region, so capturing a city flips the whole region. Borders are drawn the way Civ3 draws its culture borders: a dashed line in the nation's colour along the edge of its territory, just inside it, and nothing across the territory itself. Where two cities of one nation touch there is no line, so the nation's territory reads as a single area. Foreign land you have never seen carries no line either. Scenarios may set a city's level; otherwise it follows its size and whether it is the capital.

**Improvements** are built by workers: roads (6 work-turns on flat ground, more on rough), railroads on top of roads (12), mines on mountains and desert (12), and farms on open ground beside water (8). Rough terrain multiplies the work by its move cost, several workers on a tile add their rates, and a job is lost when its workers leave. Improvements change movement and what the square produces (see Economy).

**Economy** is Civ3's food, shields, and gold, gathered square by square. Every square yields an amount of each, set by its ground, and a city collects from **every square of its border region**, with no citizens to assign. Because each square belongs to exactly one city, two cities never collect the same square; a city founded later gathers only land nobody held, and a captured city takes its harvest to its new owner along with its land.

| Ground | Food / Shields / Gold | Ground | Food / Shields / Gold |
| --- | --- | --- | --- |
| Grassland | 2 / 0 / 0 | Forest | 1 / 2 / 0 |
| Plains | 1 / 1 / 0 | Jungle, marsh | 1 / 0 / 0 |
| Desert | 0 / 1 / 0 | Hills | 1 / 0 / 0 |
| Tundra | 1 / 0 / 0 | Mountains | 0 / 1 / 0 |
| Coast, sea, ocean | 1 / 0 / 2 | River on an edge | +1 gold |

Mountains hide whatever grows on them, then forest, jungle, and marsh replace the soil and hills. Workers add to a square: a **farm** +1 food, a **mine** +2 shields, a **road** +1 gold, and a **railroad** +1 shield and +1 gold on top of its road. A city's own square counts as roaded, as farmed if it is open ground, and yields at least one shield. Food feeds the citizens (2 each); the surplus fills a granary of `20 × (citizens + 1)` and the city grows a citizen when it is full, while a shortfall drains it and starves a citizen at a time, never below one. A city's land cannot feed more people than its food allows, so cities level off where the land runs out. Shields are the city's production each day, plus the city's own industry (what **Develop** adds), and they add up to the nation's industrial output for the industrial victory. Gold is the nation's income; the campaign script's `income_percent` scales the whole sum. The city panel shows the food balance, granary, shields, and gold; the treasury shows the daily income; selecting a square shows what it yields. Research still comes from population and industry.

Known simplifications: no zones of control, no fortress or wall effects, rivers neither slow movement nor help defenders (they water farms and add gold), ships heal only in their own ports, computer nations do not use workers and neither build nor use transports, and gold has one use so far (Develop).

## Architecture

| Crate | Responsibility |
| --- | --- |
| `fourx-sim` | Pure deterministic Rust state machine, calendar, map, combat, AI, orders, the scenario document type, serializable protocol. No Bevy, Lua, IO, or system clock. |
| `fourx-content` | Portable JSON pack schema, scenario validation, pack-relative asset paths. |
| `fourx-runtime` | Authoritative host, transactional commands, bounded Lua execution, saves/replays. No Bevy. Runs on native and WASM. |
| `fourx-server` | Headless CLI and HTTP/WebSocket service. |
| `fourx-client` | Bevy rendering, UI, input, embedded/remote transport. |
| `asset-forge` | Synthesizes the starter WAVs (`bell.wav` and the combat sound effects). |
| `scenario-forge` | Builds `world-1876.json` from curated history tables and public geographic data (coastlines, rivers, elevation, climate), then validates it like the game does. |
| `art/` (Python) | Reproducible original PNG art: SVG scenes, painterly finishing, UI kit. See `art/README.md`. |

This workspace has no dependency on `open-civ3/` or its reference code. Ordered containers, seeded integer combat, and explicit command/revision state make headless runs reproducible. Server snapshots mask uncharted terrain and enemies outside the player's vision. The spectator view reveals the campaign.

The default desktop run uses one executable for the client and embedded authoritative server. It does not require a separate server process or open a network listener. Use `--server URL` to connect to a remote server instead.

## Server

```sh
cargo run -p fourx-server -- --bind 127.0.0.1:7878 --save campaign.save.json
cargo run -p fourx-server -- --scenario world-1876 --nation russia   # choose the world and nation
cargo run -p fourx-client -- --server ws://127.0.0.1:7878/ws
```

The server sends each client a whole snapshot on connect and after every change. For the charted 1876 world that is about 0.5 MB of JSON (a save is about 0.8 MB a month in), which is fine on loopback or a LAN but wasteful over a slow link. Delta snapshots are future work.

`GET /health` reports readiness, `/pack` exposes the current pack manifest, and `/assets/` serves its PNG/WAV files. Clients receive the manifest before their first snapshot and use the same pack visuals as the server. The first authorized connection is the commander; later connections spectate. Disconnecting releases the commander slot. This is a solo campaign with remote access/spectating, not simultaneous multiplayer factions.

For non-local exposure, set `FOURX_TOKEN`, pass `--token TOKEN` to the client, and place the server behind a TLS reverse proxy (`wss://`). Do not pass secrets in public URLs. There is no lobby/account service. The default bind is loopback. WebSocket messages are capped at 16 KiB; the server assigns player authority and checks versions, revisions, and strictly increasing request sequences. Saves are trusted local files and cannot be uploaded through the protocol.

For automation: `--simulate DAYS --seed SEED --save PATH`; `--load PATH` resumes a host. Simulation JSON is written to stdout. Script/validation failures exit unsuccessfully. `cargo run -p fourx-client -- --smoke --screenshot /tmp/fourx.png` captures a rendered desktop frame and exits after 200 frames.

## Modding

Use a complete replacement pack directory containing `pack.json`, scripts, and ordinary PNG/WAV files:

```sh
cargo run -p fourx-client -- --pack /absolute/path/to/my-pack
cargo run -p fourx-server -- --pack /absolute/path/to/my-pack
cargo run -p asset-forge              # regenerate bundled audio
(cd art && .venv/bin/python build.py) # regenerate bundled art (see art/README.md)
```

The base pack is the working format example in `assets/packs/base/`. `format: 4` is mandatory; earlier pack formats are no longer read. Units have stable string IDs, names, costs, Civ3-style attack, defense, hit-point, movement, bombard, blitz, work-rate, and settler values, a land or sea domain, and sprite paths. Ships may carry land units (`capacity`, at most 16), and a design with a bombard may be lethal against land or sea targets (`lethal_land`, `lethal_sea`). All numeric values are bounded. Packs define research cost, starting treasury, victory industry, visual paths, and the campaign script.

Worlds live in **scenarios**, separate JSON documents listed in the pack's `scenarios` array (`{"id", "path"}`, paths relative to the pack directory) with one named by `default_scenario`. A scenario sets the start date, map (up to 1024 × 1024 tiles), any number of nations with their status, suzerain, colour, leader and treasury, regions, cities, starting units, and wars, and may override the pack's victory, research, and treasury rules for itself. Every cross-reference is validated at load time and the simulation never sees an inconsistent scenario. The full field-by-field specification is in [`docs/scenario-format.md`](docs/scenario-format.md).

To add a campaign, drop a scenario file into a pack, list it in `pack.json`, and run `cargo run -p fourx-server -- --pack DIR --list` to check it loads and see which nations it offers. Any nation in a scenario can be commanded with `--nation`; the others are computer-controlled. The computer nations garrison and recruit, found a few cities, and march only against nations they are at war with. Diplomacy is not implemented: wars either start in the scenario or begin when someone attacks a unit or occupies a city, and nothing ends them.

Paths may not traverse outside the pack; symlinks are canonicalized and checked. Current packs replace the entire definitions table; there is no implicit or filesystem-dependent merge order.

Scripts use **plain Lua 5.4 through OmniLua**, following the decision to use a pure-Rust interpreter for native/mobile/browser parity. There is no mlua dependency and no Bevy scripting bridge. The same interpreter executes the same script in browser offline campaigns and dedicated servers. `on_turn(context)` gets the next turn, seed (string), city count, and a `campaign` table containing the current turn, cities, units, and factions. Entity keys in that table are strings. It returns an integer `income_percent`, 25–400. The host creates a fresh sandbox for each turn, enforces a 200,000-instruction / 8 MiB budget, and removes host services, dynamic loading, randomness, and stdout printing. Scripts currently customize these effects; arbitrary custom gameplay commands and UI scripting are not exposed yet. A failure leaves the campaign unchanged. Saves include the exact pack and script, so they replay independently of later content edits.

## Terrain format

The map is a Civ3 rectangle that stands **upright** on screen, north up and east right, with every other row shifted half a tile, as in Civ3. The simulation keeps a square grid of logical coordinates `(x, y)` (a tile's native Civ3 column is `x - y` and its row `x + y`, up to a fixed offset) and embeds the rectangle in it: the cells around the rectangle are *void*, behave as if off the map, and are drawn as black space. All eight neighbours of a tile, the four that share an edge and the four that touch at a corner, are one step away on that grid. The world is 256 tiles wide and 684 rows tall (a 598 × 598 square holding 175,104 tiles); Dawn Straits is 12 × 36 in a 30 × 30 square. A square is built from **layers**, the way a Civ3 tile is: a *base terrain* (ocean, sea, coast, grassland, plains, desert, tundra), a *relief* on land (flat, hills, mountains), a *cover* (forest or jungle on any land relief, marsh on flat ground), and *rivers* along its edges. The simulation reads each layer on its own: movement cost and defense come from the best of relief and cover, and the economy table above reads them the same way. A scenario stores the layers as stacked rows (`terrain`, `relief`, `cover`) and run-length rivers; see [`docs/scenario-format.md`](docs/scenario-format.md).

Rendering uses 128×64 diamonds (authored at 1.5× for crisp scaling) and depth-sorted overlays, drawn in layers too. Terrain draws on the **dual grid**: each rendered diamond has the four surrounding tile centers as its N/E/S/W vertices, and a cell is up to three sprites:

* **ground** (`visuals.terrain`): a sheet of 16 columns of 2:1 diamond cells (the client derives the cell size from the image width). Each vertex carries a digit (grassland 0, plains 1, desert 2, tundra 3; a water vertex takes the land beside it), and the cell is `index = (4*S + E)*16 + 4*W + N`. The first 16 rows hold all 4⁴ combinations. Rows 16 and 17 hold six tonal variants of each pure cell (`256 + 4*(k-1) + digit`, `k` in 1..=6); their borders equal the base cell, so the client may pick them by a position hash without breaking any seam.
* **water** (`visuals.water`): the same grid, painted over the ground with alpha. Digits are land 0, coast 1, sea 2, ocean 3; water that touches land always draws as coast, so a shoreline cell is two sprites and open water keeps its depth.
* **rivers** (`visuals.rivers`): 16 columns, one per mask of the four half-edges that meet at a tile corner (bit 0 north-east, 1 south-east, 2 south-west, 3 north-west), with one row per meander variant. A river runs along the edge between two land tiles, so rivers always read as a continuous line.

That preserves tile-center terrain and smoothly joins coasts. It is freshly implemented from the documented geometry under `open-civ3/reverse-engineering/blending.md`; no reference implementation or Civ3 asset loader is used. Relief and cover are sprites that stand on the tile: `forest`, `pine` (forest on slopes and tundra), `jungle`, `marsh`, `hills`/`hills_dry`/`hills_cold`, and `mountain`/`mountain_dry`/`mountain_cold` (by the ground beneath); forested and jungle-covered relief uses dedicated combined sprites, with dry and cold variants. Border ribbons are projected onto the same surface and share its painter order, so nearer peaks obscure terrain and border segments behind them. See [`docs/terrain-surfaces.md`](docs/terrain-surfaces.md) for the clean-room behavior, art contract, and reproducible `terrain-study` scenario. The base pack's art is 1.5× the drawn size for the terrain sheets (cells 192×96), and 2× for the rest: units 160×160 (ships 256×192), city/relief PNGs 256×224, farm and mine overlays 256×128, scaled by the client; transparent padding defines their anchor. The big terrain sheets are palette PNGs (no dithering, so cells that share an edge still agree on it).

**City skins.** Every nation has a `flavor` in its scenario entry (`western`, `latin`, `orthodox`, `arab`, `east_asian`, `south_asian`, `southeast_asian`, `african`, `steppe`, `native`, `oceanic`; default `western`), and the pack's `visuals.cities` maps each flavor to its own 256×224 city sprite: brick and slate for the north-west, terracotta and bell towers for the Mediterranean and Latin America, onion domes for Orthodox lands, domes and minarets for the Islamic world, upswept tiled roofs and pagodas for East Asia, chhatris and spires for the subcontinent, stilt houses and stupas for South-East Asia, thatched huts in palisades for Africa, felt tents on the steppe, tipis and mounds for the indigenous Americas, and thatched halls under palms for the Pacific. A pack must supply all eleven. The flavor is cosmetic: the simulation never reads it, but it travels with the snapshot, so remote clients draw the same skins. The 1876 world assigns it per nation (Japan, Qing China, and Korea are `east_asian`; the Ottomans, Egypt, and Persia `arab`; Ethiopia `african`; Mongolia `steppe`; Hawaii and Tonga `oceanic`).

**Fog of war and borders.** `visuals.fog` is a 9×9 sheet of tile diamonds (2304×1152 as shipped) indexed by the sight state of a tile's four corners, each 0 never seen, 1 remembered, or 2 in sight, as `(3*W + N) * 9 + 3*S + E`; a corner's state is the best of the four tiles that touch it, so the black of the unexplored and the dim of the remembered fade into clear sight across the tiles instead of stepping. The fog sheet must be sampled without filtering (its half-open diamonds partition the plane) and is drawn above terrain, improvements and surface borders, below cities and units. `visuals.borders` is four diamonds (up-right, down-right, down-left, up-left), each holding a white dashed line along one edge, which the client tints with the owner's colour. A city that was seen once and has since left sight is drawn dimmed, as Civ3 does. A unit sees five tiles in every direction of the grid (a diamond on screen); cities see the same.

**Unit clips.** The optional `visuals.units` block gives a design frame-by-frame art, keyed by design id. Each entry has a `frame` (the cell size in pixels, anchored like the design's sprite) and five `clips`: `idle` and `run` loop, `attack`, `victory`, and `death` play once. A clip is `{"sheet", "frames", "ms"}`: a PNG of `frames` columns and eight rows, one per facing in the order Civ3 stores its unit strips (south-west, south, south-east, east, north-east, north, north-west, west), with `ms` milliseconds a frame. A sheet may be at most 2048 pixels on a side, so that it loads everywhere WebGL2 does. A design without an entry is drawn from its `sprite`. The client fetches a sheet the first time it is needed and keeps only the standing and walking ones loaded. The base pack animates all ten designs: land units in 160×160 cells, ships in 256×192.

**Combat dress.** The optional `visuals.combat` block restyles fights on screen (the rules are in [`docs/combat-animation.md`](docs/combat-animation.md)). `sounds` maps a cue to a WAV inside the pack: `volley`, `charge`, `gun`, `broadside` (the shot of that style), `hit` (every blow), `fall`, `sink`, and `yield`. A cue left out is silent. `styles` maps a unit design id to how it fights: `volley` (the default for land designs that attack), `charge`, `gun` (the default for designs that bombard), or `broadside` (the default for ships). Unknown cues, designs, or styles, and paths that leave the pack, are rejected when the pack loads. The base pack ships eight synthesized cues and sets cavalry to `charge`.

The pack also ships a UI kit (`ui/`: brass-framed panels, plates, buttons, bars, flags, parchment, icons) that the client does not reference yet.

## Platforms

- Desktop: Linux/X11/Wayland, Windows, macOS through Bevy. Linux requires the usual window/audio development packages (ALSA, udev, X11/Wayland).
- Web: `wasm32-unknown-unknown`, WebGL2, pure-Rust Lua. Install the Rust target and Trunk, then `cd web && trunk serve`. Offline local play is the default. Append `?server=ws://localhost:7878/ws` for a server; HTTPS pages require `wss://`. Remote packs load through the server's HTTP(S) asset URL and require appropriate same-origin hosting or CORS configuration.
- Android: the client exposes a `cdylib` and `android_main`, with the `android` feature enabling Bevy NativeActivity. APK metadata bundles the assets; `cargo apk run -p fourx-client --lib --no-default-features --features android` uses an Android SDK/NDK/toolchain. Desktop features must stay disabled.
- iOS: an exported C entry and XcodeGen project configuration live in `platforms/ios/`. Build a static client library for `aarch64-apple-ios`, generate the project, select a signing team, and run from Xcode. See `platforms/README.md`. Platform SDKs, signing, and device testing are required and have not been performed here.

Native gameplay and native/web compile checks are recorded in `VALIDATION.md`. Cross-platform source support does not imply that every device build has been tested.
